**Verdict:** the schema and the state list match the table, the attempt index holds, and the scheduled transport is closed by construction. But `transition!` is neither locked nor atomic, and one method can move a proposal back to `validated`. Fix those before commit.

**Before commit**

- **A path back to approvable exists.** `record_broker_outcome!` (`app/models/order_proposal.rb:96`) takes any `to`. Calling it with `:validated` on a `submitted` row writes `validated`, then the audit raises on the unknown kind `proposal_validated`. With no transaction, the status change stands. Restrict `to` to `filled`/`cancelled` and wrap `transition!` in a transaction.
- **`transition!` checks in-memory state with no lock.** Two concurrent approves both pass `from.include?(status)`. The second's `update!` succeeds (a pk update), writes a second `proposal_approved` audit that append-only makes permanent, then the attempt insert hits the index. The index prevents the duplicate order; the audit trail still lies. Use `with_lock` and re-check inside `transition!`, or compare-and-swap with `where(id:, status: from).update_all`. The comment "the caller holds the row lock" is a promise the model should keep itself.
- **`start_submission!` is two writes outside a transaction.** A crash between them leaves `submitting` with no attempt, which the sweep cannot `record_unknown!`. Same fix: one transaction.
- **The `record_*` methods mutate the attempt before checking the state.** `record_submitted!` on a `filled` proposal sets the attempt's `broker_order_id`, then raises. Transition first, then the attempt. None verifies the attempt belongs to the proposal.
- **`OrderProposal#warnings` drops `unavailable`;** `Report#warnings` includes it. The step 3 acknowledgement list will be built from the model and skip the "not checked" rules §0.8 requires acknowledging.
- **`require_approver` is public**, so it is an action on every controller. Make it private.
- **Specs are narrative, not generated.** Missing rows: 19 (`submission_unknown` → `submitted`, `submission_reconciled`), 23 (`cancelled`), `start_submission!` refused from `proposed` (the most important refusal), `expire!` and `reject!` from `submitted`, and terminal × everything. Write one matrix spec: every status × every transition method, raise unless the table allows.

**Step 2 or 3**

- **Halt split matches PRD §5.4 3 and Flow 1's banner** (entries disabled, exits available) and Flow 8 (pause stops creation and submission). Two gaps: `trip_rule_halt!` returns early when already halted, so a drawdown trip during a daily-loss halt is swallowed and the daily reset reopens entries under a drawdown breach. The spec asserts this. Take the later `resets_at` and record the rule. A lapsed halt also clears silently with no `rule_halt_cleared` row, against §0.16. Add a lock like `pause_for_token!` before the evaluator can trip concurrently.
- **`submission_reconciled` is chosen by `attempt.reconciled_at`**, which nothing sets. An explicit `record_reconciled!` is honest by construction.
- **Shadow reconciliation has no transition.** A shadow proposal sits in `submitted`, and `record_submitted!` refuses `submitted`, so the matcher in row 14 cannot link the Schwab-direct order or audit. Needs a link method.
- **The registry's audit row is written before validation and invocation** (`app/models/agent/tools.rb:32`), so a refused or failed write is audited as "used" with no outcome, outside the tool's transaction. Log after `invoke` with ok or error and the `ToolCall` id. "Never the account hash" is a schema convention, not enforced. The scheduled transport is closed: `for(:scheduled)` requires `read_only?` and `tool` raises on `scheduled && !read_only`. The remaining hole is a write tool that forgets `read_only: false`: it silently becomes a scheduled, unaudited read tool.
- **Sizing is right for decimal inputs:** floor to Integer, budget to cents, BigDecimal stored as strings in jsonb. Float inputs crash the refusal branch, since `Float#to_s('F')` raises. Coerce at the boundary before the Turbo frame passes params. A nil quantity from a refused sizing is not blocked at the model; the evaluator must hard-fail it.

The `pending` attempt outcome is not in §1's enum. `NULLS NOT DISTINCT` needs Postgres 15; dokku is pinned to 17, so that is fine.
