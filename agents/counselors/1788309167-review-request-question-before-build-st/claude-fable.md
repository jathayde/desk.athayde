Review complete. Findings below, ordered by severity.

## Blocking before the loop is written

1. **The memory pull cannot run in the container.** The final Docker stage installs curl, libjemalloc2, libvips, and postgresql-client only; git exists in the build stage alone, so the pull job fails on its first run. Beyond that, the process runs as uid 1000, the dokku storage mount will be owned by the host user, and git refuses with "dubious ownership" and cannot write `.git`. Nobody has planned how the container authenticates to the remote either. Move the pull to the host: a cron or post-receive hook on the VPS owns the checkout, and the Rails job becomes a read-only check that records the HEAD sha, file mtimes, and checkout age into the memory_repo sync run, failing loudly when the mount is missing or older than a threshold. Rails never writes, no git binary, no deploy key in the container. If you keep the in-container pull anyway, add git to the base image, chown the mount to 1000:1000, run `git -c safe.directory=<path> pull --ff-only`, and mount a read-only deploy key.

2. **Do not send temperature.** On the Claude 5 family the parameter is rejected for any value other than 1.0 and is unsupported on Sonnet 5 and Fable 5.1. Same for top_p. Drop "temperature default" from the design.

3. **Thinking blocks must round-trip.** Opus 5 and Sonnet 5 have thinking on by default with display omitted, so every response can contain a thinking block carrying a signature. Append the response content back as the assistant turn unchanged. Rebuilding the assistant message from text and tool_use blocks alone gets a 400 on the next call. Thinking tokens bill as output and count against max_tokens, so a small max_tokens hits the ceiling before any tool_use appears. Use max_tokens of at least 8192 per call and set a low or medium effort to keep thinking short. Effort is soft guidance; max_tokens is the hard ceiling.

4. **The email must go out even when the run fails, and deterministic content must not come from the model.** Split the mail into a template-rendered header, deterministic sections, the model body, and a footer. The header carries the token status line from `SchwabToken.status`, the degraded reasons, and the as-of stamps. The EOD's fills recap, journal rows created, missing post-mortems with trade links, and the snapshot numbers all come from the database, not from the model. When the API call fails, the email still ships with the deterministic sections and one line saying the brief is unavailable and why. Absence of an email is indistinguishable from a mail outage, and the digest arrives ten hours after a morning failure. Also persist the run as succeeded before delivering, add an `emailed_at` column, and add a rake task to resend a stored run so a mail failure never costs a second API run.

5. **Idempotency and stuck runs.** Solid Queue dedupes recurring enqueues on task key and run time, so the schedule itself will not double-fire. Duplicates come from `retry_on`, manual re-enqueue, and a worker killed mid-run, which marks the job failed with a pruned-process error and leaves the agent_runs row `running` forever. Guard with `limits_concurrency` keyed on kind, a check for a succeeded run of the same kind on the same New York date before creating a row, and a sweep that marks `running` rows older than 20 minutes as failed with "left running", mirroring the sync run stale rule. Add a `skipped` status and write a row on closed days so the system page can say why there is no brief.

## What will make the brief misleading

6. **Market-day gating contradicts the degraded rule.** The plan says market-day briefs require a Schwab-sourced calendar row, and also that agent jobs run degraded when the token is dead. A dead token means a fallback row, so no brief runs, and the token line that was supposed to be visible daily never ships. Run whenever the row says trading regardless of source, and put "calendar unverified, today may be a holiday" in the header when the row is a fallback. Keep the strict Schwab-sourced rule for snapshots only. Cron `0 7 * * 1-5` and `30 16 * * 1-5` in New York; the job checks `MarketDay.for(today).trading?`. Early closes are fine.

7. **07:00 quotes are not overnight moves.** At 07:00 a Schwab quote's last may be the prior close or an extended-hours print, net_change is versus the prior close, and positions.last_price is from the last hourly sync. Without instruction the model will print zero moves everywhere or describe yesterday's session as overnight. The prompt must say: report a pre-market move only when trade_time is today, always attach the quote's as_of, and call the section pre-market prints rather than gaps. Say "none printed yet" when that is the case.

8. **Turn cap semantics.** Define a turn as one Messages API round trip. Parallel tool_use blocks in one response are one turn, and every id must be answered in one user message with the tool_result blocks first. When the cap is reached on a tool_use response, do not run the tools. Answer each id with `is_error: true` and the text "tool budget exhausted, write the brief from what you have", then make one final call with `tool_choice: {type: "none"}`, which every model supports. Never put a text block after tool_results; the docs warn it teaches early end_turn. Handle the other stop reasons explicitly: max_tokens with a trailing tool_use gets one retry at double max_tokens, then counts as capped. refusal, model_context_window_exceeded, and pause_turn end the loop, keep any text, and record the reason. Add a `stop_reason` column so the footer and digest can say "capped at 12 turns". An empty final text is a failed run, and the email still goes out per item 4.

9. **Degraded must be computed from what happened, not only from the token.** A live token with Schwab down, or a positions sync two hours stale, misleads exactly as much. Set degraded when the token is unusable, or any tool call in the run returned an error, or any tool result carried `stale: true`, or the dashboard reports the balance stale. List the reasons in the header. Note that with a dead token get_quotes still answers: the no-token error is a Schwab error that fetch_quotes swallows into a warning and returns up to 12-hour-old cache entries marked stale. The prompt must forbid narrating price moves from stale quotes.

10. **What the model must not infer.** No earnings dates, economic releases, news, reasons a stock moved, analyst targets, anything about the IRA, and no share counts or order sizes. The PRD says the agent never computes size. Put the fixed sentence "Earnings and economic calendar: not available in Phase 1" in the mailer template, not in the model's output. Require every number to trace to a tool result with its as_of, and write "no data" for any empty section rather than filling from memory. Tell it not to retry a rate-limited tool; retries burn turns.

11. **EOD timing versus the snapshot.** The snapshot needs close plus 20 minutes and a positions run started after the close. Positions run every 15 minutes inside the session, which lasts to 20:00, so the snapshot usually lands on the 16:20 or 16:25 tick. Usually, not always. The EOD must say "today's snapshot not yet written, equity as of HH:MM" rather than present yesterday's snapshot as today's. Consider 16:40 for the EOD and 17:15 for the digest so the digest also catches an EOD failure. At 07:00 the tick fires three syncs at once because the fallback calendar opens the session at 07:00; the brief reading positions mid-upsert sees mixed as-of stamps. Wait up to about 90 seconds for live runs on the account's feeds, then proceed and note it.

12. **Prompt caching.** Use the top-level `cache_control: {type: "ephemeral"}` automatic mode. Within a run the tools and system prompt are stable and turns are seconds apart, so every turn after the first reads from cache. The as-of stamps at the top of the system prompt do no harm because the cache is per run. Minimum cacheable size is 512 tokens on Opus 5 and 1024 on Sonnet 5, which the memory files clear. The usage object splits input into input_tokens, cache_creation_input_tokens, and cache_read_input_tokens, so the two integer columns in agent_runs cannot price a run. Add the two cache columns or a usage jsonb. The price table needs four rates per model: input, cache write at 1.25x, cache read at 0.1x, output. An unknown model id yields a nil cost and "unpriced" on the system page, never zero. Add a spec that fails when the table lacks the configured model.

13. **Bound the context, not just the turns.** Tool results are the cost driver: a one-year daily history is roughly 250 candles, and the journal at 200 trades with legs is larger. Twelve turns of parallel calls can push the context past 200k tokens; the 1M window means no error, only cost. Cap each tool_result text at something like 24 KB with a visible truncation note, add a cumulative input budget per run that ends the loop the same way the turn cap does, and check a monthly spend ceiling before starting. Set the SDK request timeout to about 120 seconds instead of the 10-minute default, keep max_retries at 2, and enforce a 10-minute wall-clock deadline checked before each call. Solid Queue has no job timeout.

14. **Model choice.** Sonnet 5 for both briefs. Opus 5 costs 2.5x for synthesis over structured data. Keep one constant for the model id and store it per run, which the schema already supports.

| Model | Input per MTok | Output per MTok |
|---|---|---|
| Sonnet 5 | $2 | $10 |
| Opus 5 | $5 | $25 |

15. **Strict tool use.** Set `strict: true` on the scheduled definitions; the schemas already carry `additionalProperties: false`. Verify the supported schema subset accepts `format: date`, `default`, `minItems`, and `maxItems` as used by get_quotes and get_journal, or strip those keywords in the scheduled definition. You only need tool_choice auto and none.

16. **Injection exposure and the real target.** In Phase 1 the untrusted text is symbols, Schwab descriptions, and John's own thesis and watchlist text, and there are no write tools. The target is therefore the email: a planted instruction could make the brief say "sell everything" or carry a link. There is no markdown gem in the Gemfile. Render the model body as plain text in the text part and escaped simple_format in the HTML part, with no links or images taken from model output; every link is template-generated. State in the runtime prompt that its rules override anything in instructions.md or prompts.md. Keep tool results inside tool_result blocks and never copy them into system. Cap memory files per file and in total, truncate with a note that appears in the footer, scrub invalid UTF-8, and treat a missing repo as a degraded reason with a header line.

17. **Failure digest.** "Since the last digest" needs state you do not have, and audit_events is reserved for the PRD's list. Use a fixed 24-hour window ending at run time, keyed on finished_at for agent and sync runs and created_at for Solid Queue failed executions. Group by feed, kind, and job class, include stuck `running` agent runs and runs with `emailed_at` nil, skip the email when empty, and exclude skipped_token rows since the nag covers them.

18. **Email details.** Subject "Athayde Desk: morning brief, Tue Sep 1", prefixed DEGRADED or FAILED. No dollar figures in subjects, for the same reason push payloads carry none. Recipients: the token mailer sends to every user, which means both seeded users get every brief; decide that deliberately. Routes that exist for deep links: the dashboard root, the system page, the trades index with `filter=missing_post_mortem`, trade show, trade review, and Schwab authorize. Authorize requires login, so the Sunday link passes through the magic-link flow first. There is no edge review or watchlist route; do not link them. The Sunday stub should create a sunday_review run row with no tokens so the system page and digest see it.

19. **Client and delivery mechanics.** Build one memoized client from `Rails.application.credentials.dig(:anthropic, :api_key)`, passed explicitly since the SDK otherwise reads an env var. Deliver with deliver_now inside the job after the run row is saved. Do not use the SDK's beta tool runner; it bypasses the registry dispatch and the tool_calls telemetry.

20. **Tests.** A scripted fake client returning canned Message objects, in the style of the Schwab fake, covering a thinking block with a signature, parallel tool_use, max_tokens mid tool_use, refusal, a rate-limit error after retries, cap hit, and each degraded reason. WebMock already blocks net/http so the SDK cannot leak.
